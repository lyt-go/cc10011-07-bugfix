# 实时指标计算与监控大盘平台

面向实时指标计算引擎、多维度下钻分析、告警阈值管理、指标异常检测、数据服务开放与可视化看板配置的数据分析与应用工程平台。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 多维下钻 × 维度映射链路

- 下钻路径新建即完整保存有序层级明细与每层配置（聚合粒度、默认度量、缓存秒数、
  数据新鲜度）；状态只能按 草稿 → 路径评审中 → 已启用 → 已归档 推进，已归档为终态。
- 启用时校验层级重复、跨层粒度递进、起始维度一致，并冻结路径快照（层级 + 维度口径 +
  映射版本）；并发启用只保留一个快照，其余请求返回 409 冲突。
- 旧路径兼容转换（`POST /api/drilldown/{id}/convert`）与新建路径共用
  `app/services/drilldown_path.py` 里的同一套归一化与校验实现。
- 维度映射规则生效时同步写入标准维度映射结果（`GET /api/dimensionmap/standard`，
  含历史版本）；下钻启用快照与分层聚合结果引用同一份口径，映射口径变化可通过
  快照映射版本与当前映射版本核对。
- 分层聚合明细数据集（`GET /api/drilldownagg`、`GET /api/drilldown/{id}/aggregation`）
  随下钻状态同步更新，逐层记录新鲜度、来源批次、快照版本，历史数据保持可读。
- 回填批次（`POST /api/drilldownagg/backfill`）按批次号幂等，同一批次只写入一次；
  失败或中断后清理残留、从上一完整批次继续，允许重试并记录异常原因。
